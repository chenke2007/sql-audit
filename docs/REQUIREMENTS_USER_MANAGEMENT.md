# 用户管理与 RBAC 权限体系 — 需求文档

版本: v1.0
日期: 2026-05-16
状态: 已确认

---

## 1. 背景与问题

SQL Audit System 目前是一个无状态的 Web 工具，任何人打开页面即可使用，没有用户概念。在企业内网环境中存在以下问题：

- **无法区分操作者**：谁分析了哪条 SQL、谁添加了数据源，完全无记录
- **缺乏权限控制**：DBA 和开发人员的操作权限没有区分
- **分析历史丢失**：刷新页面后分析结果全部消失
- **数据安全隐患**：所有数据源对所有访问者可见

## 2. 目标用户

| 角色 | 描述 | 典型操作 |
|------|------|---------|
| 管理员 | 系统运维人员，负责系统配置 | 管理用户、配置角色、管理数据源 |
| DBA | 数据库管理员 | SQL 分析、数据源管理、查看分析历史 |
| 开发人员 | 业务开发人员 | SQL 分析、查看自己的分析历史 |

## 3. 功能需求

### 3.1 用户认证

| 需求编号 | 需求描述 | 优先级 |
|---------|---------|--------|
| AUTH-001 | 用户可以使用用户名和密码登录系统 | P0 |
| AUTH-002 | 登录成功后返回 JWT Token，后续请求携带 Token | P0 |
| AUTH-003 | JWT Token 有过期时间（access token 15 分钟） | P0 |
| AUTH-004 | 支持 Refresh Token 机制（7 天有效期） | P1 |
| AUTH-005 | 用户登出后 Token 失效 | P1 |
| AUTH-006 | 密码使用 bcrypt 哈希存储，不以明文保存 | P0 |
| AUTH-007 | 新用户首次登录强制修改密码 | P1 |

### 3.2 用户管理（管理员）

| 需求编号 | 需求描述 | 优先级 |
|---------|---------|--------|
| USER-001 | 管理员可以创建新用户 | P0 |
| USER-002 | 管理员可以编辑用户信息（姓名、邮箱、角色） | P0 |
| USER-003 | 管理员可以禁用/启用用户 | P0 |
| USER-004 | 管理员可以查看用户列表 | P0 |
| USER-005 | 普通用户不能看到用户管理功能 | P0 |

### 3.3 角色与权限（RBAC）

| 需求编号 | 需求描述 | 优先级 |
|---------|---------|--------|
| ROLE-001 | 系统支持基于角色的权限控制（RBAC） | P0 |
| ROLE-002 | 预置角色：admin（管理员）、dba（DBA）、developer（开发人员） | P0 |
| ROLE-003 | 每个角色拥有不同的权限码集合 | P0 |
| ROLE-004 | 权限码采用 resource:action 格式（如 datasource:manage） | P0 |
| ROLE-005 | 管理员可以给角色分配/取消权限 | P1 |
| ROLE-006 | 支持自定义角色（二期） | P2 |

### 3.4 数据源权限绑定

| 需求编号 | 需求描述 | 优先级 |
|---------|---------|--------|
| DSP-001 | 管理员可以给角色分配可见的数据源 | P0 |
| DSP-002 | 用户只能在下拉框中看到自己有权限的数据源 | P0 |
| DSP-003 | 管理员可以看到所有数据源 | P0 |

### 3.5 分析历史

| 需求编号 | 需求描述 | 优先级 |
|---------|---------|--------|
| HIST-001 | 用户执行 SQL 分析后，结果自动保存到数据库 | P0 |
| HIST-002 | 用户可以查看自己的分析历史列表 | P0 |
| HIST-003 | 管理员可以查看所有人的分析历史 | P0 |
| HIST-004 | 分析历史包含：SQL 文本、分析结果、风险等级、时间戳 | P0 |
| HIST-005 | 用户可以删除自己的分析历史 | P1 |

### 3.6 前端适配

| 需求编号 | 需求描述 | 优先级 |
|---------|---------|--------|
| UI-001 | 未登录用户只能看到登录页 | P0 |
| UI-002 | 登录后显示分析面板和侧边栏菜单 | P0 |
| UI-003 | 侧边栏菜单根据用户权限动态显示/隐藏 | P0 |
| UI-004 | 所有 API 请求自动携带 Authorization Header | P0 |
| UI-005 | Token 过期后自动跳转到登录页 | P0 |

## 4. 非功能需求

| 需求编号 | 需求描述 |
|---------|---------|
| NF-001 | 所有密码不以明文存储或传输 |
| NF-002 | 系统继续复用现有 SQLite 数据库，不新增数据库实例 |
| NF-003 | 前端保持单文件 Vue 3 SPA 架构，不引入构建流程 |
| NF-004 | 接口响应时间不超过 500ms（99% 请求） |
| NF-005 | 支持不在公司环境开发和测试（不依赖 Oracle 连接） |

## 5. 验收标准

- [ ] 用户可以使用用户名密码登录
- [ ] 未登录用户无法访问任何功能
- [ ] 普通用户只能看到自己有权限的数据源
- [ ] 管理员可以看到并使用所有数据源
- [ ] 分析结果自动保存并可回溯
- [ ] 管理员可以管理用户和角色
- [ ] 密码不以明文存储
- [ ] 权限控制正确生效（越权请求返回 403）
